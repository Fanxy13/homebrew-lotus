Plugins

Build your own Lotus

A plugin adds commands, tools for the AI and a line under the start screen – written in zsh, Python, Node or anything that runs on a Mac. Make one in a minute, drag the ones others made into the installer, install whole packs from GitHub, and share yours.

Start in a minute

  1. Make one

    $ lotus plugin new my-tool

    A working plugin in ~/.config/lotus/plugins/my-tool: a command, a tool for the AI and a start screen line.

  2. Run it

    $ lotus my-tool

    In a new Lotus shell also as /my-tool. Ask /ai to greet someone, and it uses the plugin's tool.

  3. Change it

    $ lotus plugin check my-tool

    Edit its plugin.conf and programs; check says what is wrong and how to fix it.

What a plugin can bring

Commands

command todo = todo.zsh

lotus todo add milk runs todo.zsh add milk. As many commands as it needs – but not one of Lotus' own names.

Tools for the AI

tool add = todo.zsh add

/ai and the web chat use them when they help: "put milk on my list". Lotus checks every value and asks first when the tool changes something.

A start screen line

startup = todo.zsh count

One line under the start screen. It is made in the background, so a slow program never slows down the start.

plugin.conf

One setting per line. The example is the todo plugin.

plugin.conf
# what you see
name        = todo
title       = To-do
version     = 1.0
description = A small to-do list in the terminal

# what it may do: limited (a sandbox) or full
access      = limited
network     = no

# lotus todo …
command todo = todo.zsh

# a tool for the AI, with its parameters
tool add               = todo.zsh add
tool add.level         = act
tool add.description   = Add a to-do to the user's list.
tool add.param text    = text, required, What there is to do

# under the start screen, at most every 60 seconds
startup       = todo.zsh count
startup.every = 60

A tool's program gets its values as arguments and as LOTUS_ARG_<NAME>, prints its answer for the AI and ends with 0 (done), 1 (failed), 2 (wrong arguments) or 3 (the user has to decide). Parameter types: text, int(1,999), enum(a|b|c), path. Every program finds its own data folder in LOTUS_PLUGIN_DATA and the theme's colors in LOTUS_COLOR_KEY and friends.

Limited or full access

limited

The default. The plugin runs in a macOS sandbox: it reads only its own folder and writes only its data folder. No internet unless it says network = yes, no keychain, no controlling other apps, nothing of your files or Lotus' settings – and never the AI's API keys.

full

For plugins that work with Lotus itself or your files. It runs with your rights and can load Lotus' own functions: its settings, colors and look. Lotus asks you before it installs one, and again whenever one of its files changes.

A plugin is code that runs on your Mac. Lotus always shows what a plugin brings and may do before it installs it. Give full access only to plugins from people you trust.

Lotus checks each one, shows what it brings and may do, lets you leave some out and asks once, naming the ones with full access. lotus plugin install does the same with folders, git links and <git URL>#<folder> on the command line.

Plugin packs

A pack installs several plugins at once, with the settings that make them work together – a preset to share. It is a GitHub repository (or a folder) with a pack.conf:

pack.conf
name        = creator-kit
title       = Creator kit
description = Videos from YouTube songs, a to-do list and GitHub

# the plugins: a git URL, a folder in a repository, or a folder of the pack
plugin = https://github.com/you/lotus-rsvm
plugin = https://github.com/Fanxy13/homebrew-lotus#plugins/todo
plugin = ./weather-art
plugin = https://github.com/you/lotus-github off

# their settings and files
set rsvm.RSVM_OUT = ~/Movies/RSVM
files rsvm        = ./rsvm

Install one

lotus plugin install https://github.com/you/creator-kit

Lotus shows the pack and each plugin with what it may do and the settings it brings, and asks once. A pack never gives a plugin more access than its own plugin.conf asks for.

Make one

lotus plugin pack my-setup

Your plugins as a pack: the ones from git by their link, your own copied in, with their settings. Put the folder on GitHub and share the link.

Try one

lotus plugin install https://github.com/Fanxy13/homebrew-lotus#packs/examples

The three example plugins at once – hello with full access stays off until you turn it on.

Live Server, like in VS Code

Type /liveserver in a project folder – in VS Code's terminal too. It serves the folder on this Mac – and to your phone in the same Wi-Fi – opens index.html or, when there is none, a menu of all its pages, and reloads the browser whenever you save a file. Change only CSS, and only the styles swap – the page keeps its place.

Where

/liveserver the folder you are in
/liveserver docs another one
/liveserver about.html that page
/liveserver stop the ones in other windows
Port 5500 or the next free one, or --port 8080
--local only this Mac

Only your Wi-Fi

This Mac and the devices in the same Wi-Fi – a device from another network gets no answer, and only the Mac's own names work. Nothing outside the folder, no hidden files like .git or .env.

Full access, and why

It has to read your project folder and open the browser – a limited plugin sees only its own folder. Python's standard library, nothing to install.

Share it

Put your plugin's folder in a git repository, with its plugin.conf at the top. Anyone can install it:

$ lotus plugin install https://github.com/you/lotus-todo

and gets your newest version with lotus plugin update todo. Lotus is open source under the MIT license – open a pull request to list your plugin in plugins/README.md.

Examples to start from

todo

Limited. A command, three AI tools (add, list, done) and a start screen line; its list lives in its data folder.

github

Limited, with the internet, in Python: stars, forks and the newest release of a repository, and GitHub's zen on the start screen.

hello

Full access: Lotus' own look, your theme and the features that are on.

liveserver

Full access, in Python: Live Server like in VS Code – it reads the folder you start it in (LOTUS_PWD), serves it to this Mac and your Wi-Fi and reloads the browser when you save.

All plugin commands

CommandWhat it does
lotus pluginYour plugins: what they bring, what they may do, whether they are on
lotus plugin new <name> [full]A working plugin to start from, limited or with full access
lotus plugin check <name or folder>Check a plugin.conf or a pack.conf – what is wrong and how to fix it
lotus plugin installerDrag plugin folders and packs in, or paste a git link – several at once
lotus plugin install <folder, git URL or pack>Install plugins or a whole pack – it shows what they bring and may do, and asks
lotus plugin pack <name>A pack of your plugins and their settings, to share
lotus plugin info <name>Everything about one plugin
lotus plugin on / off <name>Turn it on or off; its files stay
lotus plugin allow <name>Allow a plugin with full access again after its files changed
lotus plugin update <name>The newest version of a plugin installed from git
lotus plugin uninstall [name …]Uninstall plugins with their data (asks first) – a name in any case, several at once, or none to choose them from a list
lotus features plugins offTurn off all plugins at once
